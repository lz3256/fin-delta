# Prompt v2 调试记录

用户的第一次 T4 dev 运行：200 题，schema 合法率 97%，数值正确率 1%，verified 正确率 0%。所提供的案例多次复用了 subtract、100 和 answer=20，出现算式与答案直接矛盾。原 prompt 有固定 120-100=20 示例，存在锚定/照抄嫌疑；尚未通过受控对照证明它是唯一原因。

修订内容：移除具体数字答案示例，用字段/类型描述 JSON；要求按问题选实体、指标与期间，并使 answer 等于最终步骤的计算值。明确通常比例/增长以 fractional ratio 表达，但源数据有混合百分比尺度，仍需独立标签审查。

只在原 dev cohort 顺序的前 20 题复测，与旧预测的同 20 题计数比较。模型、数据内容、答案和评分容差不变。结果属于提示工程诊断，不能写成 SFT/DPO 提升。

现在预测、训练与评测记录 prompt SHA256；compare 拒绝把不同或未知 prompt 版本的结果当作相同条件下的训练比较。

后续 SFT 前必须重新 export-sft；DPO 必须重新生成候选。旧的 bootstrap 偏好携带旧 prompt，不能直接训练。先不要执行原 Notebook 第 7–12 步；待此次诊断确定正式协议后，使用新的 RUN_ID 重新建立 Base/SFT 比较。

版本 v2 是待验证的调试假设，不保证性能提升。源百分比标注问题不能通过自动把预测乘/除 100、挑选正确尺度来掩盖。
